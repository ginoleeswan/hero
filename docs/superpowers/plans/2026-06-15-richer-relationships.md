# Richer Relationships (Lane 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add LLM-generated relationship kinds (`love_interest`, `mentor`/`protege`, `rival`) to the `hero_relationships` graph — produced by Claude Code in-session, not an API pipeline — and surface them in a new Connections section on the character screen (native + web).

**Architecture:** A schema migration adds a `confidence` column, a `relationships_ai_status` progress ledger on `heroes`, and changes `rebuild_hero_relationships()` to preserve `source='ai'` rows. The graph's existing `get_related_heroes` RPC serves the new kinds unchanged. A new `getConnections` db helper + `useConnections` hook feed a new `ConnectionsSection` component that reuses the existing `RelatedHeroStrip`. Edges are generated by Claude in-tab (documented runbook) and written via `execute_sql`.

**Tech Stack:** Expo / React Native, TypeScript (strict, no `any`), Supabase (Postgres + PostgREST RPC), TanStack Query, Jest + @testing-library, `mcp__supabase__apply_migration` / `execute_sql` / `generate_typescript_types`.

**Conventions:** Work directly on `master` (no feature branch). Screens never import `supabase`. `StyleSheet.create` for styles. Never use `Flame-Bold`. Run `yarn test:ci` for tests.

### Task 1: Schema migration — confidence column, status ledger, rebuild guard

**Files:**
- Create: `supabase/migrations/<ts>_relationships_ai.sql` (use a real UTC timestamp, e.g. `20260615120000_relationships_ai.sql`)
- Modify (regenerate): `src/types/database.generated.ts`

The migration adds two columns and redefines `rebuild_hero_relationships()` with **only one line changed** vs. the current definition in `20260610123000_create_hero_relationships.sql`: the `truncate` becomes a guarded `delete`. The full function body is reproduced verbatim below with that single change applied.

- [ ] **Step 1: Write the migration file**

```sql
-- Lane 4: richer relationships (AI-generated edges).
-- Adds a confidence score for AI edges, a per-hero generation ledger, and makes
-- the rebuild preserve source='ai' rows (it previously truncated everything).

alter table public.hero_relationships
  add column if not exists confidence real;

alter table public.heroes
  add column if not exists relationships_ai_status text;

-- Redefine the rebuild so it no longer wipes AI-generated rows. ONLY the first
-- statement changed: `truncate` -> `delete ... where source <> 'ai'`. The rest is
-- copied verbatim from 20260610123000_create_hero_relationships.sql.
create or replace function public.rebuild_hero_relationships()
returns void
language plpgsql
as $$
begin
  delete from public.hero_relationships where source <> 'ai';

  -- enemies + allies — resolve each name to the most-popular matching hero, dedupe,
  -- then rank by that hero's popularity within (subject, kind). Cap so mega-lists
  -- stay bounded.
  insert into public.hero_relationships (hero_id, related_id, kind, source, rank, cross_universe)
  select hero_id, related_id, kind, 'comicvine', rank, cross_universe
  from (
    select hero_id, related_id, kind, cross_universe,
           row_number() over (partition by hero_id, kind order by issue_count desc nulls last) as rank
    from (
      select distinct on (h.id, k.kind, nm.nm_name)
        h.id as hero_id,
        m.id as related_id,
        k.kind,
        m.issue_count,
        (m.publisher is distinct from h.publisher) as cross_universe
      from public.heroes h
      cross join (values ('enemy'), ('ally')) as k(kind)
      cross join lateral unnest(
        case when k.kind = 'ally' then h.friends else h.enemies end
      ) as nm(nm_name)
      join public.heroes m on m.name = nm.nm_name and m.id <> h.id
      order by h.id, k.kind, nm.nm_name, m.issue_count desc nulls last
    ) resolved
  ) ranked
  where rank <= 60;

  -- teammates — heroes that share a team. Bounded to the top 40 by popularity.
  insert into public.hero_relationships (hero_id, related_id, kind, source, rank, cross_universe)
  select hero_id, related_id, 'teammate', 'comicvine', rank, cross_universe
  from (
    select hero_id, related_id, cross_universe,
           row_number() over (partition by hero_id order by issue_count desc nulls last) as rank
    from (
      select distinct on (h.id, m.id)
        h.id as hero_id,
        m.id as related_id,
        m.issue_count,
        (m.publisher is distinct from h.publisher) as cross_universe
      from public.heroes h
      join public.heroes m on m.id <> h.id and m.teams && h.teams
      where h.teams is not null and array_length(h.teams, 1) > 0
    ) resolved
  ) ranked
  where rank <= 40;
end;
$$;
```

```typescript
import { getRelatedHeroes, type RelatedHeroCard } from './heroes';

export interface HeroConnections {
  loveInterests: RelatedHeroCard[];
  mentors: RelatedHeroCard[];
  proteges: RelatedHeroCard[];
  rivals: RelatedHeroCard[];
}

const EMPTY: HeroConnections = {
  loveInterests: [],
  mentors: [],
  proteges: [],
  rivals: [],
};

/**
 * Richer relationship kinds (AI-generated, source='ai') for a hero, straight from
 * the `hero_relationships` graph via get_related_heroes. Ranked by the related
 * hero's popularity. sameUniverse:false — these connections cross publishers freely
 * (unlike enemies, which we keep same-universe).
 */
export async function getConnections(heroId: string): Promise<HeroConnections> {
  if (!heroId) return EMPTY;
  const [loveInterests, mentors, proteges, rivals] = await Promise.all([
    getRelatedHeroes(heroId, 'love_interest', { limit: 24 }),
    getRelatedHeroes(heroId, 'mentor', { limit: 24 }),
    getRelatedHeroes(heroId, 'protege', { limit: 24 }),
    getRelatedHeroes(heroId, 'rival', { limit: 24 }),
  ]);
  return { loveInterests, mentors, proteges, rivals };
}
```

### Task 6: `ConnectionsSection` component

**Files:**
- Create: `src/components/ConnectionsSection.tsx`

The component takes the four `RelatedHeroCard[]` lists, builds the `names` + `heroMap` inputs `RelatedHeroStrip` expects, and renders one strip per non-empty kind. It renders `null` when every list is empty so the caller can place it unconditionally. No own section header text styling beyond reusing the strip labels — the caller wraps it with its existing `SectionHeader`.

- [ ] **Step 1: Create the component**

```typescript
import { View, StyleSheet } from 'react-native';
import { RelatedHeroStrip } from './RelatedHeroStrip';
import type { RelatedHeroCard } from '../lib/db/heroes';
import type { HeroConnections } from '../lib/db/relationships';

/**
 * Richer-relationship strips (love interest / mentor / protege / rival) for the
 * character screen. Each list is already resolved to hero cards by getConnections,
 * so we adapt to RelatedHeroStrip's (names + heroMap) API and let it render.
 * Returns null when there's nothing to show.
 */
export function ConnectionsSection({
  connections,
  onPressHero,
}: {
  connections: HeroConnections;
  onPressHero: (hero: RelatedHeroCard) => void;
}) {
  const { loveInterests, mentors, proteges, rivals } = connections;
  const total =
    loveInterests.length + mentors.length + proteges.length + rivals.length;
  if (total === 0) return null;

  const strips: {
    key: string;
    label: string;
    kind: 'love_interest' | 'mentor' | 'protege' | 'rival';
    cards: RelatedHeroCard[];
  }[] = [
    { key: 'love', label: 'Love Interests', kind: 'love_interest', cards: loveInterests },
    { key: 'mentor', label: 'Mentors', kind: 'mentor', cards: mentors },
    { key: 'protege', label: 'Proteges', kind: 'protege', cards: proteges },
    { key: 'rival', label: 'Rivals', kind: 'rival', cards: rivals },
  ];

  return (
    <View style={styles.block}>
      {strips.map(({ key, label, kind, cards }) =>
        cards.length ? (
          <RelatedHeroStrip
            key={key}
            label={label}
            names={cards.map((c) => c.name)}
            heroMap={new Map(cards.map((c) => [c.name, c]))}
            kind={kind}
            onPressHero={onPressHero}
          />
        ) : null,
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  block: { marginTop: 2 },
});
```

   ```sql
   insert into hero_relationships (hero_id, related_id, kind, source, rank, cross_universe, confidence)
   values (...)
   on conflict (hero_id, kind, related_id) do nothing;
   ```
   (`cross_universe` = subject.publisher is distinct from related.publisher.)
6. **Mark done** — `update heroes set relationships_ai_status = 'done' where id = any($batchIds);`
